## Overview

This directory contains the implementation and tests for the Office feature surface of the web-v2 server. At the root, TypeScript modules provide the runtime code: adapters.ts declares adapter interfaces and factory/helper functions for constructing office-related dependencies; handler.ts defines the dependency interface, error types, and the primary request handler for office operations; pages-entry.ts exposes the Cloudflare Pages Functions entrypoint for the Office route. Complementing those runtime files, multiple .mjs test modules exercise adapters, the handler, the pages entrypoint, and Postgres-backed quota behavior.

A small subdirectory (sql-test/) provides a disposable CI database provisioning script (setup.sql) used by the Postgres-backed tests. Together, the runtime files implement the Office request surface and dependency construction, the tests validate behavior and integration (including a Postgres-backed quota test), and sql-test supplies the database fixture required by CI jobs that run those tests. This layout groups feature code, entrypoint wiring, and tests together so developers can find implementation, integration points, and CI database setup in one place.


### File Organization

Files are organized around the Office feature: runtime code (adapters.ts, handler.ts, pages-entry.ts) sits alongside focused test modules (adapters.test.mjs, handler.test.mjs, pages-entry.test.mjs, quota.postgres.test.mjs). The sql-test subdirectory contains CI database provisioning scripts used by tests. This keeps feature implementation and its verification co-located for easier maintenance.
