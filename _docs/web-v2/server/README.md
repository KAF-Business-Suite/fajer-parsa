## Overview

The web-v2/server directory groups server-side code responsible for handling requests and related runtime types and tests. At the root level there are no documented top-level files; instead the directory is organized into focused subdirectories that contain the actual server modules and their unit tests. This directory is the server-side counterpart within the web-v2 project and serves as the locus for request handling logic and adapters used by higher-level application components.

Currently documented subdirectories include office and intake. The office subdirectory contains TypeScript modules for adapter types and factory functions (adapters.ts) as well as the primary asynchronous request handling logic with its types and runtime error classes (handler.ts), plus unit tests that exercise those modules. The intake subdirectory is present but not documented in detail here. Together, these components implement server-side adapters, error types, and the asynchronous request handler(s) that process office-related requests and include unit tests to validate behavior; they work together by providing typed adapters and a handler layer that surfaces runtime errors in a structured way for the rest of the system.


### File Organization

Files are organized into purpose-driven subdirectories (e.g., office, intake). Root contains minimal or no files and serves as a container for feature-focused server modules. The office subdirectory groups adapter definitions/factories, handler logic, runtime error types, and their unit tests together to keep related server-side code co-located and testable.
