## Overview

This directory contains the root-level project files and configuration that coordinate testing and frontend assets for the repository. At the root there is a Vitest configuration file (vitest.config.js) which defines how Vitest runs tests for the project. Numerous other root assets (static HTML, images, package.json, .gitignore, README.md, etc.) are present in the directory but are not individually documented here; they provide site previews, packaging metadata, and repository-level resources.

Two documented subdirectories organize the codebase further. The tests/ subdirectory holds Vitest test specifications (notably a single fajer-parsa.test.js at the root of tests/) used to verify behavior and guard against regressions. The web-v2/ subdirectory contains the second version of the web application surface, including root-level configuration and a dedicated server/ subdirectory focused on intake handling and its associated tests. Together, the root vitest configuration and the tests/ directory define the repository's test surface, while web-v2/ holds the versioned frontend and server intake implementation that those tests are intended to exercise. This structure supports running repository tests with Vitest and locating the corresponding frontend/server code under web-v2/ when investigating failures or developing features.


### File Organization

Root-level configuration and assets sit alongside subdirectories for tests and a versioned web frontend. vitest.config.js at the root centralizes test runner configuration; tests/ contains test specifications, and web-v2/ contains the versioned frontend and server intake implementation. This separation groups test-related concerns and the web application separately to make testing configuration discoverable and to keep frontend server code contained.

## Architecture Notes

- Testing configuration is centralized at the repository root (vitest.config.js) while test specifications are colocated in a dedicated tests/ directory to separate test definitions from implementation.
