## FP-INTAKE-01 — 14 November 2026 · existing quota and real DB transaction acceptance

**Decision:** Select the *existing* KAF `public.fajr_take_intake_slot()` server-side RPC instead of inventing a Cloudflare Pages rate-limit binding or duplicating the database. Rationale: same source of truth, existing service-role-only EXECUTE, atomic per-minute/day capacity, no extra vendor, resource or payment. Revisit adding per-IP edge protection if abuse/traffic requires it. This is a global admission cap, **not a per-IP limiter**; do not label it such. The global cap is 12 requests/minute and 100/day as implemented in the live function.

- Adapter `supabaseIntakeQuota()` performs HTTPS POST to the existing `/rest/v1/rpc/fajr_take_intake_slot` with server-only credentials; unexpected status or nonboolean response fails closed. The same KAF project origin remains pinned.
- Handler now rejects missing client IP, malformed requests, missing consent and failed Turnstile **before consuming the global quota**, then uses existing saver and receipt validation. No auto sends.
- Existing Supabase metadata confirmed `fajr_intake_configuration()` and one named vault secret record. **No secret value was read.** The live `fajr_receive_web_request` function does not itself use `intake_control`; the application must invoke the quota RPC. No trigger enforces it. This is why the server integration cannot be bypassed when intake is opened.
- **Real database transaction QA:** one synthetic `example.invalid` contact, existing global quota RPC, service-role intake receipt, authorized Fajr Office `fajr_office_list` readback through existing KAF/Fajr membership, exact request-ID replay. All checks **PASS** within an explicit BEGIN/ROLLBACK transaction, no actual customer identity returned. Follow-up readback: **3 original requests**, **0 synthetic test rows remaining**, **0 office audit rows**. This proves database operations inside one transaction, **not** external HTTPS-to-Office or a persistent customer record.
- All commits to PR #22 still avoid mounting `functions/`; the main site remains static, four-language Production unchanged.
- Reference: [Cloudflare Pages Functions bindings](https://developers.cloudflare.com/pages/functions/bindings/), [Workers rate-limit semantics](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/) (approximate, per location, not assumed supported by this Pages project). Existing KAF DB atomic quota was preferred for portability and free-first constraints.

**Remaining external step:** authorized Cloudflare Preview runtime binding of exact origin, server-only Supabase credential and Turnstile secret, then one real HTTPS synthetic submission and permitted Office readback. Until then the public intake feature stays OFF. Secret or Production changes require the separate owner-controlled release gate.
